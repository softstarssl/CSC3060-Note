# Lec1

| 英文术语                                    | 中文翻译               | 核心解释/关联概念                                             |
| --------------------------------------- | ------------------ | ----------------------------------------------------- |
| **Computer System**                     | 计算机系统              | 由协同工作的硬件和系统软件组成，用于运行应用程序。                             |
| **Moore‘s Law**                         | 摩尔定律               | 芯片上晶体管数量约每两年翻一番，成本减半。是信息革命的核心驱动力。                     |
| **Bit**                                 | 位/比特               | 信息的基本单位，值为0或1。                                        |
| **Byte**                                | 字节                 | 通常由8个比特组成，是内存寻址的基本单位。                                 |
| **ASCII / Unicode**                     | ASCII / Unicode 编码 | 字符的二进制表示标准。ASCII用于英文字符，Unicode涵盖全球语言。                 |
| **Context**                             | 上下文                | 赋予二进制序列具体含义（如整数、字符、指令）的解读规则。                          |
| **Compilation System**                  | 编译系统               | 将高级语言（如C）源代码转换为机器可执行的二进制文件的工具链（预处理器、编译器、汇编器、链接器）。     |
| **Compiler**                            | 编译器                | 将高级语言语句翻译成低级机器语言指令的程序。                                |
| **Linker**                              | 链接器                | 将多个编译好的目标文件合并成一个可执行文件的程序。                             |
| **Executable Object File**              | 可执行目标文件            | 包含机器代码的二进制文件，可直接加载到内存中执行。                             |
| **Process**                             | 进程                 | **操作系统对正在运行的程序的抽象**。每个进程都感觉自己在独占硬件。                   |
| **Thread**                              | 线程                 | 一个进程中的执行单元，共享进程的代码和全局数据。**轻量级进程**。                    |
| **Context Switching**                   | 上下文切换              | 操作系统保存当前进程状态、恢复下一个进程状态，以实现进程间切换的机制。                   |
| **Virtual Memory**                      | 虚拟内存               | **操作系统为每个进程提供的独占整个内存空间的抽象**。它通过地址翻译和磁盘交换实现。           |
| **Virtual Address Space**               | 虚拟地址空间             | 一个进程所能“看到”和使用内存地址范围。在32/64位系统中通常是巨大的。                 |
| **File**                                | 文件                 | **操作系统对所有I/O设备的抽象**，即“一切都是字节序列”。                      |
| **Abstraction**                         | 抽象                 | 隐藏复杂细节，提供简洁模型的核心思想（如文件、虚拟内存、进程）。                      |
| **CPU (Processor)**                     | 中央处理器              | 执行存储在内存中的指令的引擎。核心部件：PC、寄存器文件、ALU。                     |
| **Register**                            | 寄存器                | CPU内部的小型、极快的存储单元，用于存放当前计算的操作数。                        |
| **PC (Program Counter)**                | 程序计数器              | 存放下一条要执行的指令的内存地址的寄存器。                                 |
| **ALU (Arithmetic/Logic Unit)**         | 算术逻辑单元             | 执行算术和逻辑运算的CPU部件。                                      |
| **Main Memory (RAM)**                   | 主内存                | 处理器在执行程序时用来存放程序和数据的临时存储设备。                            |
| **Bus**                                 | 总线                 | 贯穿整个系统的一组电子管道，负责在组件间传递信息。                             |
| **I/O Device**                          | 输入/输出设备            | 系统与外部世界联系的通道（如鼠标、键盘、显示器、磁盘、网络适配器）。                    |
| **Cache Memory**                        | 高速缓存               | 小而快的SRAM存储器，作为CPU与主存之间的临时存储区域，用于弥补速度差距。               |
| **Locality**                            | 局部性原理              | 程序倾向于重复使用最近使用过的数据和指令（时间局部性），以及附近的数据（空间局部性）。这是缓存有效的基础。 |
| **Memory Hierarchy**                    | 存储器层次结构            | 组织不同速度、容量和成本的存储设备（寄存器、缓存、内存、磁盘等）形成的金字塔结构。上一级作为下一级的缓存。 |
| **Operating System (OS)**               | 操作系统               | 介于应用程序和硬件之间的软件层，是资源的管理者和控制者。                          |
| **Kernel**                              | 内核                 | 操作系统的核心部分，常驻内存，负责管理进程、内存、设备等核心资源。                     |
| **System Call**                         | 系统调用               | 应用程序向操作系统内核请求服务的编程接口。                                 |
| **Amdahl‘s Law**                        | 阿姆达尔定律             | 对系统某部分进行优化时，整体性能提升取决于该部分所占的时间比例。**指导优化方向**。           |
| **Concurrency**                         | 并发                 | 系统同时处理多个任务的一般概念（宏观上同时，微观上可能交替）。                       |
| **Parallelism**                         | 并行                 | 利用并发使系统运行得更快（真正的同时执行，需要多个物理核心）。                       |
| **Instruction-Level Parallelism (ILP)** | 指令级并行              | 处理器在同一时刻执行多条指令的特性（通过流水线、超标量等技术实现）。                    |
| **Data-Level Parallelism (DLP)**        | 数据级并行              | 单条指令同时处理多个数据的特性（通过SIMD、向量指令实现）。                       |
| **SIMD**                                | 单指令多数据             | 一种DLP实现方式，如对数组中的所有元素同时执行加法。                           |
